# User guide

Use Copilot freely, but give it a clear job, the smallest useful context, and a
stopping condition. The goal is not fewer useful interactions; it is fewer
expensive loops that do not improve the result.

For current prices and announcement dates, see [README.md](README.md).

## What consumes AI credits

Copilot Chat, Copilot CLI, Copilot cloud agent, Copilot Spaces, Spark, code
review, and third-party coding agents consume AI credits.

Code completions and next edit suggestions remain unlimited on paid plans and do
not consume AI credits.

The cost of a model interaction comes from:

* input tokens sent to the model;
* cached input or cache-write tokens;
* output tokens generated by the model; and
* the model's current token prices.

## A cost-efficient default workflow

1. State the outcome and stopping condition.
2. Name the files, symbols, errors, or tests that matter.
3. Start with **Auto** or the least expensive model that can do the work.
4. Ask Copilot to inspect before editing when the codebase is unfamiliar.
5. Review the diff at each meaningful checkpoint.
6. Run the smallest relevant test or validation command.
7. Stop or restate the goal when the agent drifts.

## Choose the right mode

| Task | Good starting mode | Why |
| --- | --- | --- |
| Local implementation details | Code completions | Unlimited on paid plans |
| Explain a function or error | Focused chat | Small, direct context |
| Apply a known multi-file plan | Edit or agent mode | Autonomy is useful after scope is clear |
| Diagnose terminal work | Copilot CLI | Tools and command output stay close to the task |
| Complex architecture or debugging | Reasoning model | Extra reasoning maps to the problem |
| Large pull request review | Copilot code review | Broad coverage; private-repository reviews use AI credits and Actions minutes |

## Use Auto by default

Auto model selection evaluates task complexity and model health. On supported
surfaces, it routes at natural cache boundaries rather than switching models in
the middle of a task.

For paid Copilot plans, Auto provides a **10% discount on model costs** in
Copilot Chat, Copilot CLI, GitHub Copilot app, and Copilot cloud agent.

Use manual model selection when:

* you need a model-specific capability;
* policy or data-residency requirements narrow the choice; or
* you are comparing quality and cost on a controlled task.

Avoid repeatedly switching models inside one session.

## Protect your cache

Caching allows a model to reuse conversation context instead of processing the
same large prefix as fresh input on every turn. Cached input is usually
substantially cheaper, but cache behavior and rates are model-specific.

### Actions that can invalidate the cache

* Switching models mid-session
* Changing reasoning effort
* Changing the context-size tier
* Enabling or disabling tools or MCP servers
* Returning after the cache has expired

GitHub documents cache expiry after **24 hours for OpenAI models** and **1 hour
for most other models**.

### Cache-safe session habits

1. Choose the model, reasoning level, and toolset before starting the task.
2. Keep them stable while the task is in progress.
3. Use `/compact` before moving to a new phase of a long CLI session.
4. Use `/new` or `/clear` when switching to an unrelated problem.
5. After a long break, compact a large old session or start a focused new one.
6. Put stable repository facts in concise custom instructions instead of
   pasting the same setup into every prompt.

> [!TIP]
> Auto model selection protects cache boundaries by changing models only when a
> new session starts or after `/compact`, not in the middle of active work.

## Control Copilot CLI context

Every prompt, response, tool result, custom instruction, and tool definition
occupies the context window.

Useful commands:

```text
/context
/compact
/compact focus on the authentication module
/new
/clear
```

Use `/context` to see whether messages, instructions, built-in tools, or MCP
tools are consuming the window. Copilot CLI automatically starts compaction at
about 80% usage, but manual compaction is useful before a phase change.

Large command output can be especially expensive. Prefer targeted test output,
filtered logs, and focused file reads over broad dumps.

## Set a session limit

AI credit session limits are in public preview for Copilot CLI.

Interactive session:

```text
/limits set max-ai-credits 50
```

Non-interactive run:

```text
copilot -p "Fix the failing authentication test" --max-ai-credits 50
```

Remove an interactive limit with `/limits unset`.

Session limits are soft: a response already in progress can finish after the
limit is reached. GitHub recommends a value above 30 credits because many model
calls can cost more than 20 credits.

## Prompt for less waste

Use this template:

```text
Goal: <specific outcome>
Scope: <files, folders, APIs, or errors to inspect>
Constraints: <what must stay unchanged>
Verification: <tests or checks that prove completion>
Stop when: <clear completion condition>
Before editing: summarize the likely change in two sentences.
```

Better:

```text
Inspect the authentication route and its direct tests. Find the smallest change
that fixes the redirect loop. Keep the public API unchanged. Do not edit until
you can explain the root cause.
```

Avoid:

```text
Look at this repo and improve everything.
```

## Separate research, planning, and implementation

Large all-in-one sessions accumulate context quickly.

Use three focused phases:

1. **Research:** identify files, dependencies, and risks.
2. **Plan:** use deeper reasoning to define the change and acceptance criteria.
3. **Implement:** start a focused session and use a cheaper execution model when
   the plan is clear.

This keeps each phase's context relevant and makes retries less expensive.

## Use Chronicle to learn from your sessions

Copilot CLI Chronicle can analyze your private session history:

```text
/chronicle standup last 3 days
/chronicle tips
/chronicle cost tips
/chronicle improve
/chronicle search billing
```

Use it to find:

* repeated prompts that should become instructions;
* sessions that grew too large;
* model or tool patterns driving token use;
* recurring agent mistakes; and
* previous work you can resume instead of rediscovering.

Chronicle insights should be treated as normal Copilot CLI model interactions
that consume AI credits; GitHub does not publish a separate Chronicle charge.

For Business and Enterprise users, an administrator must allow the **Store local
sessions in the Cloud** policy for cross-device syncing. Sessions are private to
the user by default.

## Verify efficiently

Repeated rewrites cost more than a focused review and targeted checks.

```text
Review only this diff for functional regressions, missing tests, and surprising
behavior. Prioritize concrete findings with file references.
```

Good verification habits:

* run the smallest relevant tests first;
* filter verbose command output;
* review the actual diff before continuing;
* use linting and security scans as deterministic guardrails; and
* ask for a full suite only when the change warrants it.

## Monitor your own usage

Business and Enterprise users can review **Usage this cycle** under Copilot
settings. If a user-level budget applies, the view shows consumed credits
against the budget.

Treat the number as a signal:

* High usage can be justified by a migration, incident, or complex refactor.
* Repeated broad prompts, model hopping, and unverified retries are better
  coaching targets than raw usage alone.

## Individual-plan note

Current paid-plan totals are 1,500 credits for Pro, 7,000 for Pro+, and 20,000
for Max, including variable flex allotments. Existing annual Pro and Pro+
subscribers who stayed on legacy request-based billing continue to use premium
requests rather than token-priced UBB and do not receive new models and
features.

Additional AI credits cannot be purchased for subscriptions bought through
GitHub Mobile on iOS or Android.

## Quick checklist

* Use Auto unless you have a reason not to.
* Keep the model, reasoning level, and tools stable during a session.
* Start a new conversation for a new problem.
* Compact long CLI sessions before a new phase.
* Use completions freely for local coding.
* Set a session limit for bounded experiments.
* Run `/chronicle cost tips` periodically.
* Verify with targeted, deterministic checks.
